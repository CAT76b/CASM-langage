Toutes les instructions du CASM (C++ asembly) et comment les utiliser.
CASM version 2 beta.
Tous droits réservés au dévelopeur du projet.
Les lettres xxx sont utilisés pour représenter un espace vacant qui doit être rempli.
Les constantes sont déclarées par # (decimal) ou $ (hexadecimal)

=====SECTIONS=====

section.data =>section dans laquelle on déclare toutes les variables

section.code =>section dans laquelle on met le script

=====VARIABLES=====

crt i_xxx, xxx =>crée une variable et lui donne une valeur (mettre i_ (int), f_ (float) ou s_ (string) au début
				 du nom de la variable pour la typer)

set xxx, xxx =>change la valeur d'une variable (variable soulignée avec ~~)
    ~~~

=====ORDRES===========

prt --> xxx   =>affiche le contenu de la variable
	\-> "xxx" =>affiche le texte brut

lct xxx =>lit une entrée et la met dans la variable indiquée

header "xxx.casm" =>appelle un header

psh xxx =>met la variable indiquée dans la stack pour les donner comme argument à une fonction externe

lod xxx =>charge la première variable de la stack dans la variable spécifiée

ext  	=>arrete le programme

ret  	=>retour à la fonction courante (return en cpp)

rnd xxx, y =>génère un nombre aléatoire entre 0 et y stocké dans la variable (ici représentée par xxx)

slp xxx    =>marque un temps d'arret spécifié en millisecondes (int ou float)

tme xxx    =>récupère le time stamp actuel en secondes et le stocke dans la variable spécifiée (float)

gpu xxx    =>affiche la forme donnée (après avoir configuré les registres présents dans le header GPU_d_registers.casm) donnée
			 et l'affiche aux coordonnées indiquées: pixel, rect, voidrect, circle, voidcircle, map

ipf xxx    =>règle la vitesse d'exécution des instructions de l'émulateur (instructions per frames), prend uniquement des constantes en dur (sans déclaration # ou $)

disk xxx   =>ouvre le fichier spécifié (entre guillemets)

wrt xxx, xxx =>écrit dans le dernier fichier ouvert la string du premier argument à l'emplacement (la ligne) du second argument (int)

rad xxx, xxx =>lit la ligne spécifiée par le second argument (int, le numéro de ligne en sachant que ligne 1= 0) et écrit son contenu dans le premier argument (string)

gtc xxx, xxx, xxx =>retourne dans le 1er argument (int) la valeur ASCII de la lettre lu dans la string du 2e argument (string), la lettre à lire est indiqué par un int en 3e argument (0=1ere lettre)

error xxx         =>initialise le label d'erreur pour les instructions protégées (si une instruction protégée à une erreur, elle saute au label initialisé)
                    pour protéger une instruction, il faut rajouter à la fin de l'instruction .E, exemple avec add: add.E i_a, i_b

=====ARITHMETIQUE=====

add xxx, xxx =>additionner 2 variables ou 2 nombres entre eux

sub xxx, xxx =>susoutraire 2 variables ou 2 nombres entre eux

mul xxx, xxx =>multiplier 2 variables ou 2 nombres entre eux

div xxx, xxx =>diviser 2 variables ou 2 nombres entre eux

pow xxx, xxx =>faire une puissance du nombre (ici souligné avec ~~) par l'indicateur de puissance (variable non soulignée)
    ~~~

sqr xxx     =>faire une racine carré

=====LOGIQUE=========

and xxx, xxx =>porte ET

or xxx, xxx  =>porte OU

nnd xxx, xxx =>porte Non-ET

nor xxx, xxx =>porte Non-OU

=====COMPARAISON=====

cpr xxx, xxx =>comparer

cpg xxx, xxx =>renvoit true si la variable en première position est plus grande que la deuxième

lif xxx      =>renvoit true si la variable float observée possède une valeur différente de 0 après la virgule

=====SAUTS===========

jmp xxx     =>sauter (le saut de base)
    ~~~
destination

jpt xxx =>jump if true (saute seulement si la condition observé est vraie)
    ~~~
destination

jpf xxx =>jump if false (saute seulement si la condition observé est fausse)
    ~~~
destination

"nom du label": =>défini un label

cal xxx         =>appelle une fonction locale ou externe (header)

====================

Ce projet est un langage de programmation assembleur, et possède un écosystème en 4 parties:
-la première partie qui est un compilateur qui traduit le script casm en script binaire
-la seconde partie qui est un interpréteur qui interprète le fichier binaire
-la troisième partie qui est un dump qui affiche le binaire brut et l'équivalant hexadécimal en console
-la quatrième partie qui est un émulateur qui offre à CASM une infrastructure lui permettant de développer toute sa puissance
	grace à un cpu et un gpu et chargé par un bios (et même capable de lire/écrire des fichiers!)
